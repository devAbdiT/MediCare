# MediCare PMS: End-to-End Test Script

Follow this 42-step checklist sequentially to manually verify the entire Patient Management System before final evaluation.

## SETUP (Admin)
- [ ] 1. Log in with an `ADMIN` account.
- [ ] 2. Navigate to **Service Catalogue** (`/dashboard/admin/services`).
- [ ] 3. Create a new service (e.g., "General Consultation") and set a baseline fee (e.g., ETB 500).
- [ ] 4. Navigate to **Users** (`/dashboard/admin/users`) and click **Create User**.
- [ ] 5. Create a user with the `PHARMACIST` role.
- [ ] 6. Create another user with the `LABTECH` role.
- [ ] 7. Log out and quickly verify that the new Pharmacist and LabTech users can successfully log in.
- [ ] 8. As Pharmacist, navigate to **Drugs Catalogue** (`/dashboard/pharmacy/drugs`) and add a new drug (e.g., "Amoxicillin 500mg").
- [ ] 9. Navigate to **Stock Management** (`/dashboard/pharmacy/stock`) and add inventory stock for the newly created drug.

## REGISTRATION (Receptionist)
- [ ] 10. Log in with a `RECEPTIONIST` account.
- [ ] 11. Navigate to **Patient Registration** (`/dashboard/receptionist/register`).
- [ ] 12. Register a new patient (fill in all required demographic data).
- [ ] 13. Open the newly created patient's profile.
- [ ] 14. Navigate to the patient's **Allergies** section and add an allergy: "PENICILLIN" with severity "SEVERE".
- [ ] 15. Navigate to the patient's **Conditions** section and add a condition: "Hypertension" with ICD code "I10".
- [ ] 16. Click **Book Appointment** from the patient profile. Select a Doctor, Date (Today), and Time.
- [ ] 17. From the Receptionist Dashboard or Schedule page, find the new appointment and click **Check In**.
- [ ] 18. Navigate to the **Queue Board** (`/dashboard/receptionist/queue`) and verify the patient is now actively listed in the waiting queue.

## CONSULTATION (Doctor)
- [ ] 19. Log in with the assigned `DOCTOR` account.
- [ ] 20. Navigate to **Schedule** (`/dashboard/doctor`) and open the checked-in appointment.
- [ ] 21. **Verify Alert**: Ensure the severe "PENICILLIN" allergy alert is prominently displayed on the patient's overview.
- [ ] 22. Record vitals (Blood Pressure, Heart Rate, Temperature, etc.) and save them.
- [ ] 23. Click **Order Lab Test**. Select "CBC" (Complete Blood Count) and set Urgency to **STAT**.
- [ ] 24. Navigate to the **Diagnosis** section. Write a diagnosis and include an ICD-10 code.
- [ ] 25. Navigate to **Prescriptions**. Build a structured prescription containing at least 3 distinct drugs (including the drug added to stock in Step 8) with specific dosages and frequencies.
- [ ] 26. Click **Complete Appointment**. 
- [ ] 27. **Verify**: Check that an Invoice was automatically generated in the background containing the consultation fee.

## LABORATORY (LabTech)
- [ ] 28. Log in with the `LABTECH` account.
- [ ] 29. Navigate to the **Lab Queue** (`/dashboard/lab/orders`).
- [ ] 30. **Verify**: Ensure the "CBC" test ordered by the Doctor is pinned at the top of the queue with a red **STAT** badge.
- [ ] 31. Open the order and update status to **Sample Collected**.
- [ ] 32. Update status to **Processing**.
- [ ] 33. Enter the test results: Value: "7.5", Unit: "g/dL", Reference Range: "12.0 - 15.5". Check the **ABNORMAL** box, and add an interpretation note. Submit the result.
- [ ] 34. **Verify Invoice**: (Optional check as Admin/Receptionist) Verify that the patient's outstanding invoice was dynamically updated with the CBC lab fee.

## PHARMACY (Pharmacist)
- [ ] 35. Log in with the `PHARMACIST` account.
- [ ] 36. Navigate to **Pending Prescriptions** (`/dashboard/pharmacy/dispense`).
- [ ] 37. Locate the 3-drug prescription generated by the Doctor.
- [ ] 38. Dispense the medications and mark the order as fulfilled.
- [ ] 39. Navigate to **Stock Management** and verify that the inventory stock for the dispensed drugs has successfully decremented.

## BILLING (Receptionist)
- [ ] 40. Log in with the `RECEPTIONIST` account.
- [ ] 41. Navigate to **Billing & Payments** (`/dashboard/receptionist/billing`).
- [ ] 42. Open the patient's invoice (which should now bundle the consultation and the lab test).
- [ ] 43. Record a full **Cash Payment** for the outstanding balance.
- [ ] 44. **Verify**: Ensure the invoice status strictly updates to **PAID**.
- [ ] 45. Click **Print Receipt** and verify that the generated HTML confirmation slip renders correctly.

## PATIENT PORTAL
- [ ] 46. Log in with the credentials created for the `PATIENT` during registration.
- [ ] 47. Navigate to **My Invoices** (`/dashboard/patient/invoices`) and verify the invoice displays a **PAID** status.
- [ ] 48. Navigate to **Medical Vault / Lab Results** (`/dashboard/patient/records?tab=lab`). Verify the CBC result appears with a red **ABNORMAL** badge.
- [ ] 49. Navigate to **Medical Vault / Medical Records** (`/dashboard/patient/records?tab=medical`) and verify the doctor's consultation notes and 3-drug prescription are clearly visible.

## ADMIN REPORTS
- [ ] 50. Log in with the `ADMIN` account.
- [ ] 51. Navigate to the **Admin Dashboard** (`/dashboard/admin`).
- [ ] 52. **Verify Revenue**: Check that the 'Today Collected' and 'Paid Today' KPIs reflect the payment made by the Receptionist.
- [ ] 53. Navigate to **Reports & Analytics** (`/dashboard/admin/reports`) and verify the department breakdown/appointment stats match your test session.
- [ ] 54. Navigate to **System Audit Logs** (`/dashboard/admin/audit-logs`). Review the table to verify that *all* critical state-changing actions (Registration, Order, Payment, Dispense) were systematically captured with user IDs and before/after JSON states.

## SECURITY & EDGE CASES
- [ ] 55. **Rate Limiting**: Fire 70 rapid requests to any public API endpoint (e.g., using Postman or a rapid browser refresh script). Verify that requests 61+ correctly return an **HTTP 429 Too Many Requests** error.
- [ ] 56. **Role Blocking**: While logged in as the `LABTECH` or `PHARMACIST`, manually attempt to navigate to `/api/admin/users` or `/dashboard/admin` via the URL bar. Verify that you are cleanly blocked (HTTP 403 Forbidden or redirected to a safe route by the middleware).
